# M7 Go Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Plan review and execution-method selection precede product implementation.

**Goal:** Deliver Go parity for the M0 (`support-triage`) and M3 (`order-brief`) lessons: a zero-dependency Go module, idiomatic runtimes, three-language golden parity for all 13 M0/M3 case keys, and an M7 authority chaining M6→M0 with `go vet`/`go test` and the 13 Go CLI flows against the unchanged goldens.

**Architecture:** One Go module at `go/` (Go >= 1.25, standard library only): typed contract structs, fixture loading from checked-in JSON projections, the M0 router with a deterministic fake model, the M3 bounded semaphore executor with `context.Context` fatal-drain, trace sinks on the shared `1.0` envelope with `source: "go"`, and two CLIs mirroring the TS/PY grammars. The M6 evaluator gains `--languages`; the goldens themselves stay unchanged.

**Tech Stack:** Go >= 1.25 (stdlib only) plus the existing Python gate tooling. No third-party Go modules; no cgo; no YAML parsing in Go — checked-in JSON projections of the M0/M3 scenario and worker fixtures, generated by a reviewed command and validated in CI.

**Spec:** [Accepted M7 design](../specs/2026-11-04-m7-go-parity-design.md), [D-018](../../decisions/D-018-m7-go-parity-stable-lessons.md), accepted 2026-11-04.

**Status:** Written design accepted on 2026-11-04 (PR #22). This plan is the next review artifact; reviewed-plan approval and execution-method selection are required before product implementation. No product code is included in this planning change.

## Global Constraints

- Zero third-party Go dependencies, no cgo; `go vet` and `go test ./...` clean.
- Shared schemas/contracts unchanged: results carry the required `attribution` block; traces on the `1.0` envelope with `source: "go"`; failure codes map 1:1 from sentinel errors (`ErrInvalidRoute`, `ErrUnknownTool`-free — M1 excluded; M0: `INVALID_ROUTE_DECISION`; M3: `WORKER_EXECUTION_FAILED`, `INVALID_WORKER_OUTPUT`).
- Checked-in JSON projections: `fixtures/goprojections/{support-triage,order-brief}/{scenario,workers}.json` + `fixtures/goprojections/{scenario}/attribution.json` — generated by `tools/generate_go_projections.py` (reviewed command, clean-worktree guard, diff-visible) from the YAML sources; CI validates projections match their sources.
- CLI grammars mirror TS/PY exactly: `m0 --mode direct|model --case <id> --trace <path>`; `m3 --mode sequential|parallel --case <id> --trace <path>`; one nonblank JSON result line, exit 0 domain / exit 2 tooling.
- M3 concurrency: bounded semaphore (limit 1/2 by mode), once-only invocation, `context.Context` fatal-drain on unexpected errors (M3 semantics — never M4), instrumented worker bodies proving overlap/ownership.
- The evaluator (`tools/evaluate.py`) gains `--languages` and runs Go flows for `support-triage`/`order-brief` (13 case keys); goldens untouched; TS/PY-only scenarios unchanged.
- The failure matrix: M0/M3 rows gain Go proof identities; `tools/chaos.py` learns `proof.go` entries for those rows.
- Stay offline and framework-free. Exclude cgo, third-party Go modules, YAML-in-Go, Go ports of M1/M2/M4/M5/evaluator/chaos, real providers, shared-runtime extraction.
- Publish evidence only on a clean unchanged candidate revision, after M6 (and its lower chain) pass on that same revision. Safety checks must survive `python -O`.

### Stable Interfaces

- `contracts`: `Event`, `RunResult` (+`Attribution`), failure-code constants; `json.Unmarshal` with `DisallowUnknownFields` helpers; canonical-JSON digest helpers for state-free comparisons.
- `internal/m0`: `LoadScenario`, `Route(direct|model)`, fake `ModelProvider`, `TraceSink`, `RunCase`.
- `internal/m3`: `LoadScenario`, `LoadWorkerFixture`, bounded `Executor` (semaphore + `context`), `Collector`/`Synthesizer`, `TraceSink`, `RunCase`; `WorkerExecutionError` sentinel.
- `tools/generate_go_projections.py`: `--scenario <id>` (repeatable) / `--all`, clean-worktree guard, unified diff output.
- `tools/evaluate.py --languages ts,py,go` (default `ts,py`): Go flow runner reusing the gate discipline (`go run ./internal/m0/cmd …`).

### Canonical Evaluation Set

13 M0/M3 case keys go three-language: `support-triage` 7 (`case@mode`) + `order-brief` 6. All other cases stay two-language. The matrix rows M0-F1 and M3-F1..F3 gain Go proofs; M3-F4 (unit row) gains a Go proof identity from the Go test suite.
